# コンセプト（最上位方針）

## 最優先の製品要件：txt2img（Text-to-Image）

**Image Drawerの主機能はtxt2img。推論時の必須入力は文章（prompt）だけであり、参照画像・下書き画像・人間の筆跡履歴をユーザーに要求しない。**

モデルは初期状態の白紙キャンバスから、テキストの指示に沿って自分で下書き・線画・着色・修正を**描画行動として逐次実行**し、最終的な画像を出力する。制作中のキャンバス・レイヤー・直前までの操作履歴は**モデルが自ら作った内部状態**であって、ユーザーが用意する画像入力ではない。キャンバス寸法やseed等の実行設定は受け取ってよいが、画像のアップロードを要求してはならない。

**主出力は画像**。加えて制作過程の行動履歴（DrawingEpisode）を検証・再現のため保存する。人間の実演画像や行動履歴は**学習段階の教師データ**であり、通常のtxt2img推論時の追加必須入力ではない。img2imgや参照画像を使う機能は将来の**任意の別モード**として扱い、txt2imgを置き換えない。


## 1. Image Drawerは何を学習するのか

**人間の絵師が絵を制作する「工程と、その中での判断・操作の連続」をAIに学習させる。**

AIが完成画像を一度に出すこと自体は目的ではない。人間の絵師がキャンバスを見て次の行動を判断し、色や道具を選んで筆を動かし、結果を見て修正し、次の行動を決める。その**逐次的な制作過程**を実演から学び、AI自身が実行できることを目指す。

```text
現在のキャンバス・レイヤー・道具・制作履歴を見る
  -> 次に何をすべきか判断する
  -> 色・道具・描画対象を選ぶ
  -> 筆で描く／消す／工程を移る
  -> 結果を観察・評価する
  -> 必要なら修正して続ける
  -> 完成を判断する
```

**重要**：手書き風の結果が出ても、この過程をAIが学習・実行していなければ目的を達成していない。単に決め打ちの行動列を実行できることも、学習が成功したことではない。

## 2. 下書き・線画・着色は「何をする段階か」を表す

人間の絵師は、例えば次のように描く。

1. ラフ・下書きを筆で描く。
2. 必要に応じて線を整え、レイヤーを作成・選択する。
3. 下書きの上に新しいレイヤーを重ね、色を選び、筆を動かして描き進める。
4. 描き間違いを消し、描き直し、影や質感を加えるなど修正する。
5. 結果を見て次の作業を決め、完成させる。

これは**例**であり、全員が必ず同じ順で描くという意味ではない。`sketch`、`line`、`color`、`correct` は工程の目的を表す。**`color` は「領域を一括塗りつぶす」という意味ではない**。着色中にも個々のストロークや道具選択・修正が存在する。

## 3. 変えてはいけない入力条件

- 色は**共通の固定256色パレット**から番号で選ぶ。画像や実行ごとにパレットを変更しない。
- **色とブラシは別の選択対象**。ブラシを複数用意する場合も、色番号に混ぜない。
- 下書きと、その上に重ねた着色用レイヤーを含む**複数レイヤー**を表現する。どのレイヤーに何を描いたか履歴に残す。
- 筆を動かす操作と、描画後の状態を保存・再生できる。完成画像だけでは制作工程を学習できない。
- 人間が描いた実演の履歴と、モデルが描いた履歴と、テスト用の作り物の履歴を混同しない。

固定256色の**具体的な色番号とRGB値の対応表**は開発者向け仕様でバージョン管理する。パレットの値は本コンセプトでは決めず、提案・レビュー・承認されたものだけを使用する。

## 4. 学習と描画器を分ける

- **描画器**：指定された行動をそのとおり実行し、レイヤー・筆跡・画素・履歴を更新する。これ自体は学習器ではない。
- **記録器**：人間が行った操作を「いつ何をどう描いたか」の履歴にする。
- **学習器／Policy**：履歴から、現在の状態に対して次にすべき行動を予測する。
- **評価器**：筆跡・制作過程・完成画像を用途に応じて評価する。完成画像の品質だけを学習の成功条件にしない。
- **Workflow**：制作・評価の大きな工程を組み立てる。個々の筆跡という行動列とは別の階層。

学習するのは主として**行動の意思決定**。Workflowの順序やPartの選択も将来的に学べるが、それだけの研究へすり替えない。

## 5. Part BankとCOMPOSEの位置づけ

既にある`Part Bank`・`RETRIEVE_PARTS`・`COMPOSE`は、画像部品の参照や補助的な素材利用に使うことはできる。しかし「パーツを検索して並べたら描いたことになる」という解釈は**禁止**。

人間と同じ制作行動の学習ループが成り立つ前に、Part Bankの最適化・パーツ選択学習を最優先の主経路に据えない。既存実装をただ削除するのではなく、目的と合うものは補助機能へ再配置する。
