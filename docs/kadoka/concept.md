# Image Drawer の目的：文章だけから、自分で描いて画像を作るAI

## 1. 何をするソフトか

**最終製品はtxt2img**。利用者が文章を入力すると、AIが白紙のキャンバスから実際にブラシを選び、線を描き、色を重ね、必要に応じて修正し、**完成画像を返す**。

**学習で利用者が用意するのは完成画像だけ**。タグやpromptはユーザーが選んだ抽出器が自動生成する。ペンタブの操作履歴、人間の筆跡、ラフ・下書きの中間画像を用意してもらう必要はない。

画像から「人間がどう描いたか」を逆算するのでもない。**AI自身が何度も実際に描き、生成結果と教材画像を比較し、次回の描き方を改善する**。

### 学習と生成を混同しない

\`\`\`text
学習：画像 → タグ・文章の自動抽出
                ↓
       AIが白紙から描く → 元画像と比較
                ↓
          報酬でAIの描き方を改善

生成：利用者の文章 → AIが白紙から描く → 完成画像
\`\`\`

**学習時の元画像は評価器だけが参照**。描画AIがそれを見ながら直接なぞる、完成画像をコピーする、途中画像を入力する方式ではない。

## 2. 描く工程の順序は固定する

**イラスト全般**を対象としつつ、制作の大きな順序は次のように固定する。

1. **ラフ**：全体の配置と大きな形。
2. **下書き**：構造・比率・細部を整える。
3. **本描き**：本番の形・線・面を描く。
4. **基本色**：必要な色や広い面を描く。
5. **陰影・質感**：影・光・材質を加える。
6. **仕上げ・修正**：細部を描き込み、必要な箇所を直す。
7. **完成**：画像と再生可能な制作履歴を出力。

**ラフ→下書き→本描きは必ず順番どおりに描く。** 基本色・陰影はモノクロやフラットな作品で必要ない場合だけ、理由を残して省略できる。順番そのものを並べ替えない。

**これは「普通の絵師が描く工程」を参考にした製品の制作手順を固定するもので、人間の個別の筆跡・筆運びを再現する要求ではない。**

[初めて読む制作工程の仕様](../developers/fixed_drawing_workflow_v2.md)に詳細をまとめる。

## 3. 工程内ではAIが自分で学ぶ

固定するのは工程の順番。各工程で何をどう描くかはAIが学習する。

- **色**は共通の固定256色から選ぶ。画像ごとに256色表を変更しない。
- **ブラシ**は12種類の独自プリセットを基本とし、色とは独立して選ぶ。
- **サイズ19段階、不透明度11段階、筆圧11段階**など、代表的な候補から選ぶ。圧の変化パターンも学ぶ。
- **レイヤー**、座標、描画・消去・修正をActionとして順番に記録する。
- 出力されたActionから制作途中の画像も最終画像もReplayできる。

固定された工程を通過するだけのスクリプトでは不合格。AIが試行から自分の行動選択を改善する必要がある。

## 4. 自動プロンプト抽出器は選択式

画像から学習するため、ソフトが画像を解析してタグ・文章を生成する。

**タグ抽出と文章抽出のモデルを利用者が切り替えられる**ようにする。利用者に正解promptを書いてもらうことを学習の必須条件にしない。抽出の誤り、空文、学習効果の低下も評価・記録する。

## 5. やらないこと

- ユーザーに人間の筆跡・筆圧・レイヤー履歴の収集を必須にする。
- 元画像から作者の過去の筆跡を推定して「人間の実演」と呼ぶ。
- 画像を直接一括変換するだけ、またはPart Bankの部品を置くだけで「描いた」と呼ぶ。
- ラフを飛ばしていきなり本描きをする、順序を無視する。
- AIの制作行動を固定ストロークスクリプトに置き換えて学習済みと呼ぶ。
- 正解画像を描画Policyの観測へ渡して高得点を取る。

既存のWorkflow Runtime、Part Bank、合成・検索機能は補助技術として残してよいが、**主機能の学習ループを置き換えない**。

## 6. 何をもって成功と呼ぶか

1. **画像だけ**を登録し、タグとpromptを自動抽出できる。
2. AIが**固定工程**に沿って自分自身のActionで描ける。
3. 自分が描いた画像と目標画像を比較して**モデルの選択が改善する**。
4. 学習後は文章だけで白紙から描き、**完成画像と全Action履歴**を返せる。
5. 未見の画像・文章でも品質改善が確認できる。工程の固定やビルド成功だけで「高精度」と呼ばない。

学習実行の正本は[画像だけで学ぶ契約](../developers/image_only_learning_v1.md)。固定制作工程は[工程v2](../developers/fixed_drawing_workflow_v2.md)、Actionの旧テスト契約は[制作過程v1](../developers/drawing_process_v1.md)、実装順は[計画](implementation_plan.md)を参照する。技術仕様を本書で二重定義しない。
