# 学習用画像の必要数と段階的テスト計画 v1

## 1. 何枚用意するか

**最初の実用的な目標は1,000枚。** ただし最初から画像を大量投入せず、10〜100枚の動作・学習更新検証を通す。現在のImage_drawerは完成画像だけから実際のActionを試し、RewardでPolicyを改善する研究構成であり、画像枚数だけで性能を保証できない。

| 段階ID | 画像枚数 | 80/10/10の参考分割（train / val / test） | seed | 合格を確認する対象 |
| --- | ---: | ---: | --- | --- |
| `smoke` | 10〜100枚（計画上の目標100） | 80 / 10 / 10（100枚時） | 11 | 登録→CaptionとTag→白紙からAction→Replay→Reward→Policy更新 |
| `pilot` | **1,000枚** | 800 / 100 / 100 | 11, 23, 37 | 単純な対象・色・位置、未見画像/文章の追従 |
| `limited_illustration` | **10,000枚** | 8,000 / 1,000 / 1,000 | 11, 23, 37 | 限定された人物・衣服・表情・構図・背景 |
| `scaling` | **50,000枚** | 40,000 / 5,000 / 5,000 | 11, 23, 37 | データ増加の効果、過学習、計算効率 |
| `research_large` | **100,000枚以上** | 80,000 / 10,000 / 10,000（10万枚時） | 11, 23, 37 | 幅広い画風・対象の一般化と独立人間評価 |

**これらはテスト予算の基準値であって、研究で確定した「最小必要枚数」ではない。** 近重複・同一作品をグループ化するため、グループの大きさにより80/10/10ぴったりにならないことがある。必ず実際の分割件数と重複除外件数を記録し、不足した規模を「達成済み」としない。

## 2. 画像を登録してから学習評価するまで

1. **入力画像のみ**を登録する。利用者にTXT、プロンプト、タグ、筆跡を追加要求しない。固定256色、ブラシ分離、7工程を変更しない。
2. SHAと近重複・同一作品グループを作り、**Caption/Taggerのモデル調整前に**作品単位でtrain/validation/testを固定する。派生画像と同じ元作品を異なるsplitへ漏らさない。
3. 各画像に独立のCaption抽出とTagger、タグ分類・正規化・整形を実行。**Qwen3-VL → JoyCaption Beta One → Felldude Uncensored V2**は標準のCaptionモデル列であり、ユーザーがN個へ変更可能。いずれかが拒否・空文・不正形式・一時障害なら次へ。選択モデルと全試行理由を保存する。
4. 全モデル拒否・失敗時は空欄の理由を残し、**「画像」などのダミーCaptionで学習しない**。TaggerはCaptionと独立に実行して結果を残す。
5. 実際のAction列を描画エンジンで実行し、**Evaluatorだけ**が正解画像を見る。目標画像と差分・報酬は同一rollout中のPolicyの観測へ渡さない。
6. 学習前後のcheckpointで**同一画像・seed・Action予算・Renderer・Reward条件**を揃え、固定した未見画像と未見promptで検証。少なくともpilot以降は3 seedで測る。
7. 改善したと判定できない場合は**達成失敗**として記録する。根拠なしに次の枚数へ拡張して「成功」としない。

`smoke`のテストは配線と単純図形の改善を確認するためのもの。少数のholdoutは統計的な一般化を示す試験ではない。pilot以上でも高品質を保証せず、別の固定baselineと信頼区間を比較する。

## 3. 必ず集計する項目

画像件数、重複件数、train/val/testの画像・グループ件数、タグ/Caption抽出失敗件数、Caption各モデルの拒否・失敗理由と採択数、学習対象から外れた件数、使用したモデル/指示/設定のfingerprint、各画像のrollout回数・Action数・更新前後checkpoint、報酬/画質/文章追従・固定工程遵守・不正Action率、GPU時間、95%信頼区間を報告する。

**画像1,000枚×各100回のrolloutは、100,000枚の別画像を学習したことにはならない。** `rollouts_per_image`と`total_rollout_count`を別項目にする。計算予算が同じでない実験を画像数だけで比較しない。

特にpromptの「対象」「色」「一つ/二つ」「左/右」「否定」を変えた未見文に対する結果を、画像品質とは独立に評価する。

## 4. SFW・NSFWのCaptionフォールバック専用試験

- 評価画像はSFWと**権限のある合法な成人NSFW**から、可能なら各100枚以上を用意する。これは学習に必要な画像数とは別の**Caption評価用の暫定下限**であり、画像をリポジトリへコミットしない。
- SFW/NSFWで第1・第2・第3モデルそれぞれの`refused`、`content_filter`、空出力、形式不正、ネットワーク失敗、Caption事実誤り・取りこぼし、最終成功率を分母付きで集計する。
- **第1段拒否→第2段拒否/空文→第3段成功**、第3段も拒否して全失敗、途中成功時の残りスキップ、独立Tagger継続、cache key変更を自動テストで再現する。自動テストにはモックを使い、機密な実画像や違法素材を使用しない。
- Felldude V2の作者は静止画像を動画として説明する場合があると明記している。静止画を動画・時間変化として記述した結果を品質失敗に分類して計測する。
- 評価セットが不足するときは**評価不能**と記録し、成功率を捏造しない。無拒否・NSFW全対応という保証はしない。
- 未照合`verifier_refused_unverified`は検証済みCaptionの件数に含めない。採用を検討する場合も区別して記録する。

## 5. 自動CIと実モデル評価の境界

`tests/test_training_scale_contract.py`は規模と分割・受け入れ契約を、`tests/test_joycaption_fallback.py`はモックによる第3段の拒否時切替を確認する。**両方のCIが成功しても実GPUでの抽出品質、RL学習の収束や汎用txt2img品質は未検証。** 実モデルと実画像を使った別の評価結果が必要。

参考：[SPIRAL++](https://learning-to-paint.github.io/)は単一カテゴリのImageNet約1,000枚・64×64を使った実験がある。ただしImage_drawerとはモデル・Action・目的が異なり、同枚数で収束する根拠ではない。[Paint Transformer](https://openaccess.thecvf.com/content/ICCV2021/html/Liu_Paint_Transformer_Feed_Forward_Neural_Painting_With_Stroke_Prediction_ICCV_2021_paper.html)は自己学習の代替方法も示す。いずれも枚数表を性能保証に使わない。
