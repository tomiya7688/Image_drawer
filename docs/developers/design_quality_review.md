# 品質と導線の見直し

## 1. 結論

現在の学習と推論は、動作確認用の玩具の規模にとどまっています。SDXL以上は必達の要件ですが、現状はそこへの途中ですらなく、基盤の検証段階です。これまでの測定（design_trainer.md 12章）はすべてこの玩具設定の結果で、品質の主張はできません。

## 2. 手抜き箇所の棚卸し（2026-11-08時点のmain）

| ID | 場所 | 現状 | 影響 |
| --- | --- | --- | --- |
| Q1 | `training/config.py` | `canvas_side`32、`max_actions`96。細部が描けない | 高 |
| Q2 | `training/policy.py` | 線形softmax方策。隠れ層なし | 高 |
| Q3 | `training/config.py` | 方策への入力は8x8に要約した特徴だけ（`summary_side`） | 高 |
| Q4 | `training/reward_features.py` | 手作りの暫定特徴（辺・RGB・輝度・ヒストグラム）。LPIPS・CLIP等の知覚特徴なし | 高 |
| Q5 | `training/reward.py` | `text_match`が未計算（重み0）。promptを無視しても罰がない | 高 |

## 3. 直す順序

依存関係の順に並べます。Aは導線（学習・推論の両ユーザーに効く）、Bは品質の核です。

| 順 | 項目 | 内容 | 合格条件 |
| --- | --- | --- | --- |
| A1 | Q11 | 1ファイルのモデルパッケージ（重み・設定・encoder・Reward仕様のハッシュ・版）。Adam状態は別扱い | 推論は`--model`1つで動く。ハッシュ・版の不一致を拒否する |
| A2 | Q9・Q10 | `image-drawer-train <画像フォルダ>`で登録・抽出・学習・保存を一括実行。進捗表示、自動再開、任意の`.txt`プロンプト読み込み | 画像フォルダ1つで通る。再開は最新のcheckpointを自動検出する |
| B1 | Q5 | promptに従う学習信号（text_matchの計算、promptを入れ替えた対比） | `prompt_shuffle_delta`の信頼区間下限が0を超える |
| B2 | Q7・Q8 | 読み出しのオーケストレーション（Captioner・Tagger・フォールバック・整形）と強いTextEncoder | 実イラストでCaption・Tagが生成され、文章の違いがベクトルの違いになる |
| B3 | Q1〜Q3・Q6 | 解像度の引き上げ、非線形方策、観測の拡張、学習量の拡大（torch等の依存の判断を含む） | 同じ評価で、玩具設定より汎化指標が改善する |
| B4 | Q4 | 知覚特徴（CLIP/LPIPS）のReward、Rewardの解像度 | 色・形・画風の違いにRewardが反応する（12.6と同じ測定で確認） |
| C | Q12 | 画像+文章入力、実用解像度 | 方策がB3の解像度に対応した後に設計 |

Q13は各項目の作業の中で直します。Q14（外部AIレビュー）は、各PRで利用可能な範囲を試し、取得できない理由を記録します。

## 4. 未決事項

- 学習済みモデルの配布形式（1ファイルの内容と署名）。
