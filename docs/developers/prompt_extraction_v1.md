> **対象読者：** はじめてImage Drawerの学習前処理を読む人、VLM・Tagger・学習Dataset・評価の実装者
> **目的：** 画像しか用意しなくても、人間が生成時に書くプロンプトと整合する文章条件を自動生成する。画像内容を説明できないモデルは、自動でQwen等へ切り替える。
> **状態：** プロンプト抽出の**ルーティング基盤と契約テストは実装対象**。実モデルの導入・正答率・画像から最終イラストまでの学習効果は**未測定**。

# 学習前の画像→高精度プロンプト生成

## 1. 利用者が準備するもの

> 学習に必要な外部入力は画像のみとする。
> ユーザーおよび開発者は、画像以外の補助データを用意する必要はない。
> タグ・説明文・プロンプトは、必要に応じてシステム側で自動抽出する。

画像だけを登録すれば、ソフトの内部でプロンプトを作る。TXT、タグ、キャプション、制作履歴、追加メタデータをユーザーに提出させない。モデルの接続先や使用モデルはアプリの**設定**であり、画像1枚ごとの追加学習素材ではない。

このプロンプトは**txt2imgの重要な教師条件**。画像に「青い髪の少女が2人、左に犬」と写っているのに「少女のイラスト」だけを教師にすれば、生成時に「青い髪」「2人」「左」の意味を描画AIが学びにくい。**画像に忠実であること**と**人が普段使う文章に近いこと**の両方を目標とする。

## 2. 一枚の画像から生成する内容

\`\`\`text
学習画像だけを登録
       ↓
高精度の画像理解VLM（優先）
       │ 拒否／空文／壊れたJSON／重大な内容不一致
       └─────────────→ Qwen-VL等の設定済み代替VLM
       ↓
対象・数・色・位置・構図・画風の構造化
       ↓
画像との照合（検証用VLMを設定した場合）
       ↓
同じ意味の「短文」「標準文」「詳細文」
       ↓
TextEncoder → DrawingPolicy
       ↓
固定7工程で白紙から自分で描く
       ↓
Evaluatorだけが目標画像と比較 → Trainerで学習
\`\`\`

**抽出器から得るのは元画像からの説明であり、人間の過去の筆跡ではない。** DrawingPolicyは正解画像を観測しない。

### 例：一枚のイラスト

見本に「赤いリンゴが一つ、白い背景に置かれた絵」がある場合、内部では以下を生成する。

| 内容 | 出力例 |
| --- | --- |
| 対象 | リンゴ、個数1、赤色 |
| 背景 | 白 |
| 構図 | 中央 |
| 短いプロンプト | 赤いリンゴ |
| 普通のプロンプト | 白い背景に赤いリンゴが一つ |
| 詳しいプロンプト | 中央に一つの赤いリンゴ、白背景のシンプルなイラスト |

この3文は**画像にある事実をどこまで詳しく言うかだけが違う**。詳しい方で勝手に「透明な皿」「葉の水滴」などを追加しない。

## 3. なぜ1つの長いキャプションに固定しないか

[DALL·E 3のrecaptioning研究](https://cdn.openai.com/papers/dall-e-3.pdf)と[RECAP](https://arxiv.org/abs/2310.16656)は、画像の説明をより正確で詳しいものに置き換えることが、テキスト指示への忠実度の改善につながると報告した。

一方、[2025年のsynthetic captions比較研究](https://ml-research.github.io/human-centered-genai/projects/t2i-synthetic-captions/index.html)は、詳細な説明文ばかりだと画質や多様性が犠牲になる場合があり、**説明の長さを変えて学習させる方法**が有効と報告した。

したがって最初は次の**仮の分布**を使う（実測済みの最適比率ではない）。

| 学習時に選ぶ説明 | 割合 |
| --- | ---: |
| 人間が入力しそうな短文 | 40% |
| 色・個数・関係を含む普通の文章 | 40% |
| 背景・構図・画風まで説明した詳細文 | 20% |

学習時は同じ画像から抽出した3候補を保存し、seedでどれを使ったか再現できるようにする。**生成時にユーザーが短文を入力しても使えること**を未見のプロンプトで評価する。色・個数・位置・否定を消すような過度な正規化はしない。

## 4. 精度向上のため何を構造化するか

出力を単なる一行の文章にせず、**次の情報を分けて取り出す**。

| 項目 | 何を検証するか |
| --- | --- |
| 主な対象 | 何が描かれているか |
| 個数 | 一人か二人か、1個か複数か。分からないときはnull |
| 色・見た目 | 対象と色が結び付いているか |
| 位置関係 | 左/右、前/後、上/下を取り違えないか |
| 背景 | 場所、物体、背景色 |
| 構図 | 全身・上半身、視点、遠近 |
| 画風・質感 | 線画、厚塗り、水彩など観測できる特徴 |
| タグ | 内容タグなど。Ratingと混ぜない |

[ComfyUI Support ToolのTagger/image-to-text移行設計](https://github.com/tomiya7688/comfyUI_support_tools/blob/main/doc/gui/tagger_image_to_text_migration.md)を参考に、**タグ、caption、style、ratingを同じ一つの文章に無条件で混ぜない**。別のTaggerを使う場合もカテゴリー・信頼度を区別し、モデルの自動タグが間違っている可能性を残す。

[CVPR 2026のCCCaption](https://openaccess.thecvf.com/content/CVPR2026/html/Tang_CCCaption_Dual-Reward_Reinforcement_Learning_for_Complete_and_Correct_Image_Captioning_CVPR_2026_paper.html)の考え方を参考に、**Completeness（重要情報の取りこぼし）とCorrectness（画像にない情報の捏造）を分けて評価**する。

現在のコードでは構造化JSONの検査と、**設定された独立VLMによる支持／不一致の再照合**を提供する。ただし照合モデル自身も間違えるので、\`verified_by_model\`は真実の保証ではない。実画像の正答率・検証器間の偏りは実測で報告する。

## 5. 高精度モデル → Qwen自動フォールバック

**優先順位を固定**する。

1. **高精度VLM（Primary）**：既知の画像・画風・文章指示で検証して精度が高いモデルをアプリの設定で指定する。プロバイダ名は固定せず、APIやローカルのVision modelを差し替え可能。
2. **Qwen系VLM（Fallback）**：Primaryが拒否・空文・壊れたJSON・重大な画像不一致を返したら、自動で代替する。まずは [Qwen3-VL-8B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct) 等の**実際に画像入力が可能な**ローカルVision modelを候補にする。軽量構成ではOllamaの\`qwen3-vl:8b\`などに接続できる。
3. **どちらも失敗**：空の文章や「何かの画像」などのニセ教師を保存せず、画像IDと失敗理由を記録してその画像のテキスト条件付き学習だけを停止する。**ユーザーに新しいTXTやタグを用意させない**。

### 切替とエラーの意味

| Primaryの結果 | 動作 |
| --- | --- |
| 成功・構造と画像内容に重大不一致なし | Primary採用 |
| Providerの\`refusal\`または\`content_filter\` | **Qwenへ自動切替** |
| 文章による明確な拒否 | **Qwenへ自動切替** |
| 空文字、JSON形式不正、何も説明しない汎用文 | **Qwenへ自動切替** |
| 画像にない主要対象・色・人数等を検証器が検出 | **Qwenへ自動切替** |
| タイムアウト・429・一時的な接続障害 | 設定に従いQwenへ切替 |
| APIキー不正、モデル設定不正、画像不正 | **設定エラーとして停止**。拒否と混同しない |
| Qwenも拒否／失敗 | 理由をログに残し、その画像を学習の非成功として扱う |

**NSFW画像の説明にも対応できる構成**とするが、Qwenなら必ず拒否しない／制限がない／高精度という保証はない。これは**画像の説明処理の頑健性**を高めるものであり、ローカルモデルの能力・運用条件は設定・実測結果で確認する。単純に検閲回避用の無条件な文字列の追加や、画像にない情報の捏造はしない。

**検証器も回答拒否する場合**：Primaryの説明が不十分だと判定されればQwenへ切り替える。ただし、Qwenが文章生成に成功しているのに独立検証器だけが拒否した場合は、Qwenの文章を**`verifier_refused_unverified`（未照合）**として保持する。確認済みの事実として扱わず、後続の品質測定で未照合件数を分けて報告する。検証器の拒否だけを理由に有効な代替モデルを無限に探し続けない。

**実装場所**：\`image_drawer/prompting/core.py\`（選択と検証）と\`openai_compatible.py\`（ローカルQwenを含むOpenAI互換API接続）。既存Image Drawerには実学習用Dataset/GUIがないため、**この段階では前処理の独立モジュール**。実モデルの重みやAPIキーは含まれない。

## 6. 失敗と学習再現性

- 1枚の入力画像だけで\`ImagePromptPipeline.extract(image_bytes, mime_type)\`を実行できる。モデルの選択は既存のアプリ設定。
- どのモデルが成功したか、どの理由でフォールバックしたか、何回試したかを**内部の試行記録**に残す。ユーザーには追加ファイルを要求しない。
- キャッシュには画像hash、Prompt profileとモデルID、検証器のID、抽出指示のversion等を含める。モデルを変更したら別の結果と見なす。
- モデル内部の画像から生成したプロンプトを**元画像とのペアで保持**する。タグ・説明文は外部の学習入力ではなく内部生成物。
- train/testを画像類似・派生画像グループで分け、同じ作品を別splitに分散させない。正解画像をDrawingPolicyへ入力しない。
- **最低限の精度比較**：Primary単独／Primary＋Fallback／検証器あり／なし、短文のみ／3粒度混合で、タグ・個数・色・位置の適合、誤記述、拒否率・fallback率、短い自然文への画像生成忠実度、長文画像品質を同一分割で比較する。

## 7. 生成時のプロンプトとの整合

**人間が生成時に入力する文章**は、その意味を保ったまま空白の整理だけを行い、**学習時に使ったTextEncoderと同じ入力経路**へ渡す。

例：\`青い服の少女が左に一人、犬は右。影なし\`という生成指示で、画像の枚数・左/右・服色・影なしを保持する。学習画像を説明するときも**それと同種の自然なプロンプト**を生成する。

タグを無条件にカンマで並べただけ、毎回長い文学的説明、毎回\`masterpiece\`を付けただけでは、普段の人間のプロンプトとの分布がずれやすい。**生成時の短い自然文・日本語/英語・タグ列**を独立した評価コホートで検査する。

## 8. 受け入れ試験・未完成の境界

- Primary成功ならQwenは呼ばない。**Primaryがrefusal/content_filter/空/壊れた出力**ならQwenが画像を受け取りプロンプトを生成する。
- 重要な画像不一致を画像照合器が検出した場合もFallbackする。照合器の成功は絶対的な真実の保証ではない。
- Qwenも失敗したら**汎用のダミープロンプトを絶対に教材へ入れない**。失敗を計数する。
- 出力した3種類の文章に対して、**同じTextEncoder**を使う。色・人数・位置関係を変えた未見promptでDrawingPolicyを評価する。
- モデルIDと指示文のversion、選択理由、出力候補を内部に記録。**入力ファイルは画像だけ**。
- 既存の固定7工程、固定256色、12ブラシを変更しない。

**まだ未完成**：実VLMの導入・ダウンロード・ベンチマーク、独立照合器の画質と誤検出、Taggerアダプタの本配線、ユーザー設定UI、Dataset/TrainerとのEnd-to-End接続。コードとモックテストが通っても**実画像の精度が改善したとは主張しない**。
