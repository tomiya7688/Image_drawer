# 描画行動 v1 受け入れ試験（正本）

以下は**実装契約**であり「テストの例にすぎない」ものではない。各観測点を同じ入力で再現できない実装は完了として認めない。既存のPart Bankテスト、ビルド、PNG生成成功だけでは代替できない。

機械可読な正本：[JSON Schema](schemas/drawing_episode_v1.schema.json)／[入力episode](../../tests/fixtures/drawing_process_v1/golden_episode.json)／[期待frames](../../tests/fixtures/drawing_process_v1/golden_frames.json)。後続のDrawingEngine実装は**このFixtureを自動テストで読み込むこと**。この文書を追加しただけでは描画機能が実装済みにならない。

## 0. txt2imgのEnd-to-End必須合格条件

学習モデルを使った基幹モードの入出力を検証する。

1. **外部入力はテキストのpromptだけ**（任意のキャンバス寸法・seed設定は許可）。画像／下書き／参照画像／既存DrawingEpisodeを指定せずに実行を開始できる。
2. 白背景・空レイヤー・空履歴から開始し、モデルの予測したActionを順に描画器へ適用する。プロンプトと無関係の固定スクリプトを再生して画像を返す実装は不合格。
3. モデルが作成した下書きレイヤーと、別レイヤー上での着色ストローク・修正操作を含む**逐次的な描画**を観察できる（これらを必ず同じ順にすることは要求しない）。
4. 終了時の**Imageを主出力**として得られ、追加成果物のDrawingEpisodeを再生すると同じ各中間状態と最終画像を得られる。出力がEpisodeだけ、または完成PNGだけで行動履歴がないものは不合格。
5. 推論時に人間の正解Action・完成画像・外部の下書き画像を入力に渡していないことを確認する。**学習用の人間の制作履歴は、推論の必須入力ではない**。
6. 同一seed・同一model/checkpoint・同一Prompt・同一実行設定なら、実装が定義する決定的な推論モードでAction列と出力画素が再現可能であること。モデルが未実装の間、このEnd-to-End条件は**未検証**と表示する。

本項は**モデルを用いたtxt2img**の合否を定義する。以下のGolden試験は描画器自体の合否を検証するもので、txt2img機能実装の代わりにはならない。

## A. 固定256色

### 高精度プリセット（v2側）の追加合格条件

[独自ブラシプリセットの正本](brush_presets_v2.md) と [機械可読12種の設定](brush_presets_v2.json)を参照する。実装時は次を満たすこと。

- 全12種のID・並び・デフォルト値・用途`mode`をそのまま読み込み、[静的契約テスト](../../tests/test_brush_presets_design.py)に合格する。
- [段階表と圧パターン](brush_control_levels_v2.md)の19/11/11レベル、5パターン、同点丸め、未取得値の`null`区別を[自動テスト](../../tests/test_brush_control_levels_design.py)で確認する。
- 元の筆圧73%が学習用70%に変換されても、**生値73%を保全**し、Actionの段階IDから同じ筆跡をReplayできることを検証する。
- `pressure_pattern_id`はモデルの補助予測であり、画素を描く際は各点の`pressure_level_id`を使う。パターンだけで筆跡を固定する実装は不合格。
- `select_color`／`select_brush`／`set_brush_params`が独立し、筆種別を変えても固定256色の`palette`は変更しない。
- 消しゴム2種が色を参照せず、描画ブラシでの`erase_v2`や消しゴムでの`stroke_v2`を拒否する。
- 同じブラシ・サイズ・不透明度・サブピクセル軌跡・筆圧・seed・renderer versionで、保存／再生後の画素が一致する。
- 全12種のスタンプ・エッジ・flow・粒状感・消去を検証する**v2 Renderer用の画素golden**を追加しない限り、v2の描画器完成や高精度学習成功と報告しない。

以下のA〜Dは**v1の旧goldenとの互換性試験**であり、v2の全ブラシの画素精度を代替しない。


入力色番号とRGB8の期待値：

| `color_id` | 期待値 |
| ---: | --- |
| `0` | `[0, 0, 0]` |
| `5` | `[0, 0, 255]` |
| `30` | `[0, 255, 0]` |
| `180` | `[255, 0, 0]` |
| `215` | `[255, 255, 255]` |
| `216` | `[6, 6, 6]` |
| `255` | `[249, 249, 249]` |

追加検証：全番号`0..255`で異なる256個のRGB値が取得できる。辞書順・モデル順による色番号の変更なし。`-1`／`256`／`true`／`5.0`／`null` は拒否。パレット名が`idraw-palette-256-v1`と異なるエピソードもv1としては拒否。

## B. 正本ストロークとレイヤー重ね描き（3×2画素）

[描画仕様の完全なJSON](drawing_process_v1.md#6-保存形式drawingepisode-v1)にある`events[0..13]`を**同一の実行器**へ通し、以下を確認する。fixtureに使う場合、`origin=synthetic`とし人間の学習データと混同しない。

最初の状態：白キャンバス3×2、レイヤーは空、作業レイヤー・色・ブラシ・フェーズは未選択。

1. `seq=0..5`：`sketch`レイヤーに黒（色番号0）で`(0,0)→(2,0)`の幅1pxの1ストロークを描く。
2. `seq=6..10`：新規`color`レイヤーを**上に追加**。赤（色番号180）で`(1,0)→(1,1)`を幅1pxの1ストロークで描く。
3. `seq=11..12`：同じ上レイヤーを`correct`フェーズで`(1,0)`だけ消す。
4. `seq=13`：終了し、以降の行動は拒否する。

`B`は「下書き画像を受け取って塗りつぶす処理」では**合格できない**。下書き、上層筆跡、消去が実際のレイヤーと時系列行動として保存されていることを検証する。

#### 観測点1：下書き描画後（seq=5）

```text
y=0: 黒 黒 黒
y=1: 白 白 白
```

#### 観測点2：上レイヤーの赤いストローク後（seq=10）

```text
y=0: 黒 赤 黒
y=1: 白 赤 白
```

下書きレイヤーの`(1,0)`は**黒のまま保存**されている。合成画像だけが赤になる。

#### 観測点3：上レイヤーだけ消去後（seq=12/13）

```text
y=0: 黒 黒 黒
y=1: 白 赤 白
```

ここで黒が戻るのは、上層の赤を消したため。下書きを復元生成してはいない。

#### 画素表（表示上のRGBA8）

| 位置 | seq=5 | seq=10 | seq=12 |
| --- | --- | --- | --- |
| `(0,0)` | `[0,0,0,255]` | `[0,0,0,255]` | `[0,0,0,255]` |
| `(1,0)` | `[0,0,0,255]` | `[255,0,0,255]` | `[0,0,0,255]` |
| `(2,0)` | `[0,0,0,255]` | `[0,0,0,255]` | `[0,0,0,255]` |
| `(0,1)` | `[255,255,255,255]` | `[255,255,255,255]` | `[255,255,255,255]` |
| `(1,1)` | `[255,255,255,255]` | `[255,0,0,255]` | `[255,0,0,255]` |
| `(2,1)` | `[255,255,255,255]` | `[255,255,255,255]` | `[255,255,255,255]` |

さらに、`seq=10`時点のレイヤー単体を確認する：`sketch[1,0]=[0,0,0,255]`、`color[1,0]=[255,0,0,255]`。`seq=12`以降は`color[1,0]=[0,0,0,0]`。描画のたびにレイヤーを一枚に潰す実装は不合格。

## C. 色選択・ブラシ・透明度は独立

同じ`3×2`キャンバスで実施する。

- `select_color(180)`のみでは画素は一切変化しない。`select_brush("hard_round_v1")`のみでも画素は変わらない。
- 選択した色番号180を使用し、白背景の透明レイヤーに`opacity_u8=127`の赤い1pxストロークを`(0,0)`へ描く。レイヤー単体は`[255,0,0,127]`、表示上の合成結果は`[255,128,128,255]`。
- レイヤーが選択されていないと`stroke`を拒否する。色未選択、ブラシ未選択、工程未設定でもそれぞれ拒否する。
- `erase` は選択したレイヤーだけを透明化し、他のレイヤーも`selected_color_id`も変更しない。
- `opacity_u8`を変更しても`palette[180]`のRGB値は変更されない。

## C.1 精密幾何の3種類のgolden case（必須）

[ゴールデンの入力と全期待画素](../../tests/fixtures/drawing_process_v1/golden_geometry.json)をそのまま読み、**すべてのcheckpointについて個別レイヤーのRGBA画素列と合成RGBA画素列を一致**させる。

1. `diagonal-width2-boundary`：斜め`(1,1)→(3,3)`、幅2の黒ストローク。境界`4*N==width²*D`の画素を含み、浮動小数誤差で除外しない。`(1,0)`は黒、`(0,0)`は白。
2. `retrace-alpha-once-per-action`：赤を幅1、opacity127で`(1,1)→(3,1)→(1,1)`と一回折返す。**同一Actionの重なりでも**各対象画素のalphaは127、表示RGBは`[255,128,128]`。その後、**別のAction**で同じ筆跡を描くとalpha191、表示RGBは`[255,64,64]`。
3. `erase-wide-sloped`：幅7の赤い線で画面を覆った後、幅2の斜め消去を実行。`stroke`と`erase`が同じ整数距離判定・端点・境界・クリップ規則を使い、対象レイヤー以外を変えない。

rendererのアンチエイリアス・線分ごとの重複合成・浮動小数による近似を用いて、これらの結果と異なる場合は**v1不合格**とする。各pixelの不一致箇所を表示して調査できるようにする。

## D. 不正入力を正確に拒否

少なくとも以下を個別にテストする（途中まで適用された場合は**最後に正常完了したイベント**までの状態とエラーを回収できること）。

| 入力 | 期待 |
| --- | --- |
| `seq` が0で始まらない／欠番・重複 | 拒否 |
| `time_ms` が負数／前のイベントより小さい／604800000超 | 拒否 |
| `seq`が19999超／イベントが20000件超 | 拒否 |
| `actor`欠落・不明・`origin`と整合しない | 拒否 |
| 整数値の小数・指数JSON表記（`5.0`、`5e0`）、同一キー重複 | **strict JSON readerで拒否** |
| 未作成レイヤーの選択／レイヤーID再使用 | 拒否 |
| `finish`がない／途中の`finish`以降もイベントあり | 拒否 |
| `stroke.points=[]`、1要素が座標対でない | 拒否 |
| x,yが負／画布外／浮動小数・真偽値 | 拒否 |
| `width_px=0`、`65`、`true` | 拒否 |
| `opacity_u8=0`、`256`、`"255"` | 拒否 |
| 不明な`brush_id`、`phase`、`type`、`payload`キー | 拒否 |
| `set_color`や`set_phase`で画素が変わる | 不合格 |
| palette, brush, rendererのv1識別子が一致しない | 拒否 |
| 不正な`JSON number`、NaN／無限大 | 拒否 |

追加の**負荷・原子性**テスト：16MiBを超えるファイル／イベント20,001件／総point200,001／候補探索画素が50,000,000超／レイヤー面積上限超の各入力を、途中の画素変更前に拒否する。細い線でも大きなCanvasで**全画面×全線分を走査しない**ことを処理量から確認する。

クラッシュをJournal ACK直後、Episode blobのrename直後、manifest確定直前、manifest確定直後の各位置に注入する。再起動後、ACK済みイベントを失わずDraftへ戻せるか、完成blobとArtifact参照が揃うかを検査。`finish`のないDraftを完成Episodeにしない。`orphan`／`broken`とその理由が記録されること。

混在episode：`actor=human`が下書きを描き、`actor=model`が上層に描き、`actor=human`が消すという3つの区間を同一episodeへ記録する。`origin=mixed`、各actorが正しく再生できること、Dataset builderがモデルstrokeを教師正解に含めないことを確認。

正当な入力での2回の再生は、各イベント直後のレイヤーRGBA画素列と最終画面のRGBA画素列が**完全一致**。PNGエンコーダの圧縮出力byte列は一致要件に含めない。

## E. 工程は筆跡と混同しない

- `set_phase("sketch")`、`set_phase("color")` は**工程ラベルの記録**。それだけでレイヤーや画像は生成されない。
- `sketch -> color -> correct`はBの**例示**であり全エピソードの必須順ではない。`correct -> sketch`等もイベント意味論が有効なら許す。
- `COLOR`というWorkflow Stepが登場しても「1回の画像変換のみ」で終了する実装はv1の描画工程の受け入れ条件を満たさない。**少なくとも操作種別・選択・stroke列を含む`DrawingEpisode`を出力する**。
- 再生できない画像だけの`Artifact`を`DrawingEpisode`と偽ってはならない。各イベントの境界で状態を検査できること。

## F. 学習と推論（描画器の完成後）

学習機能のDone条件は**描画器のDone条件と別**。以下を必須とする。

1. `origin=human`、利用許諾・データ由来が記録済みの**実際の描画イベント**から、各`events[n]`の直前状態と次アクションの教師対を作成できる。`synthetic`／`derived`を人間のデモとして扱わない。
2. 同一traceの未来の操作や完成画像を入力特徴に混ぜない。train/validation/test分割はエピソード単位（同じ作品の分割跨ぎなし）。
3. 学習器が**何らかの更新可能パラメータ**を持ち、checkpointとして保存・読み込みでき、同じ状態とseedで同じ行動を予測する。単なる固定の`if phase=="sketch"`などを「学習した」と呼ばない。
4. 行動種別の予測、固定256色の色番号分類、ブラシ選択、strokeパラメータ、終了判断の指標を個別に記録する。対象の出現しないクラスの指標を捏造しない。
5. held-out操作予測と、モデルの行動を順次`DrawingEngine`へ適用するclosed-loop描画の**両方**を検証する。人間の軌跡再生だけでclosed-loopを代用しない。
6. テスト用に**教師行動を単純に暗記できる小規模training smoke**を用意して、損失・checkpoint復元・異なる入力からの実行を検証する（学習性能そのものの主張はしない）。人間の制作過程を学習した成果と呼べるのは、許諾付きの実演データを使った評価結果がある場合のみ。

## F.1 人間の制作過程を学習できたと言うための精度評価

[DrawingPolicy精度仕様](drawing_policy_accuracy_v1.md)と[人間の実演データ品質](drawing_data_quality_v1.md)は、学習実装時の**規範的合否条件**とする。

- 実演とモデル・system・syntheticのactorはイベント単位で区別し、作品／作者単位に漏洩のないtestを準備する。
- `create_layer`、`select_layer`、`color_id`（256クラス）、`stroke/erase`の可変長点列・幅・透明度、`set_phase`、`finish`を別head／条件付き出力として検証する。
- 人間の履歴に対するoffline次アクション予測と、**モデル自身が1筆ずつ描くclosed-loop**の評価を両方実行する。
- 動作保証（Replay完全一致）と、未知作品・未知作者での学習精度改善は別ゲート。失敗したら「高精度」と報告せず、データ量と信頼区間を添える。
- 1種類だけのbrushやAction maskによる合法率を高性能の根拠にしない。未見のPrompt、色、修正、長い線の失敗例も報告する。

## G. 実装差分・PRのレビュー用チェック

PRは、どの`DrawingState`／`DrawingAction`フィールドを追加したか、該当するA〜Fの検証項目を本文に書くこと。仕様未実装なら「未実装」と書く。新仕様の反映は以下を満たすこと：

- [ ] 正本`drawing_process_v1.md`と相違しない
- [ ] A〜D：再生と異常系の自動テストがある
- [ ] E：Workflowの描画工程が行動履歴と結び付く
- [ ] F：学習を実装したときは、学習のDone条件を満たす
- [ ] 既存Runtime・Part Bankテストを壊していない
- [ ] CIのpytest/build/インストール済み成果物検証が成功する

**A〜Eを完了していない状態で「人間と同じ制作工程の実装済み」と宣言しない。Fを完了していない状態で「制作過程の学習済み」と宣言しない。**
