# イラストの7工程：固定する順序と、AIが学習する操作

## 1. これだけ知れば全体が分かる

Image Drawer は **文章からAI自身が絵を描くtxt2img**。学習時に人が用意するのは完成画像だけ。タグ・文章は選択可能な抽出器が作り、AIは白紙に実際に描いて、元画像との評価結果から上達する。**実際の人間の筆跡を集めたり逆算したりしない**。

**固定するのは描く工程の順序だけ**。鉛筆をどこから動かすか、何色を使うか、何回描き直すかは、固定スクリプトではなくAIが判断する。

```text
文章（生成時）／画像だけを登録して抽出した文章（学習時）
  ↓
① ラフ → ② 下書き → ③ 本描き → ④ 基本色
  ↓
⑤ 陰影・仕上げ → ⑥ 修正・確認 → ⑦ 完成画像＋再生可能なAction履歴
```

**すべての工程を順番に通過する。工程自体はスキップ不可。** モノクロ線画で基本色が不要なときや、フラット画で影が不要なときでも、該当工程に**入って確認した事実と理由を記録してから**次へ進む。「何も描かなかった工程を通過する」ことと「工程を飛ばす」ことは別。

ここでいう「本描き」は必ずしも黒のインク線画ではない。厚塗り・水彩風でも**本番の形や面を確定する工程**を指す。固定工程は一般的な制作手順を参考にしたImage Drawerの共通ルールであり、**すべての絵師が必ず同じ順番で描くという事実の主張ではない**。

## 2. 工程別の許可／禁止一覧

**共通で許可するもの：** 選択中の工程で使えるレイヤーの選択、固定256色からの色選択、独自12種類からのブラシ選択、19段階のサイズと11段階の不透明度の変更、サブピクセルの`stroke_v2`（筆圧11段階＋パターン）、必要な`erase_v2`。ブラシの推奨用途はヒントで、**工程ごとに道具の種類を強制固定しない**（厚塗りでも線画でも成立させるため）。

| 工程 | やってよいこと（何を学ぶか） | やってはいけないこと | 次へ進む条件 |
| --- | --- | --- | --- |
| **① ラフ（`rough`）** | 全体の配置・大まかな形、ラフ用レイヤーで描く／消す | 下書き・本描き・色用レイヤーへ描く、次を飛ばす | **roughレイヤーに実際の有効な一筆以上**、画素変化が残る |
| **② 下書き（`sketch`）** | 比率・形・細部を整える。下書きレイヤーで描く／消す | ラフや後工程レイヤーの上書き、直接本描きへ飛ぶ | **sketchレイヤーに有効な一筆以上**、画素変化が残る |
| **③ 本描き（`final_drawing`）** | 最終形・線・面を確定。黒の線に限定しない | 原画像をコピーする、ラフ・下書きだけで本描き完了扱い | **final_drawingレイヤーに有効な一筆以上**、画素変化が残る |
| **④ 基本色（`base_color`）** | 面や主要色を塗る。線画の**下**の基本色レイヤーに描く | 下の線を消す、既存線画を色で覆う、直接画素一括変換でごまかす | **実際の着色**。モノクロ線画で不要なら理由付きレビューのみ可能 |
| **⑤ 陰影・仕上げ（`shading`）** | 影・光・質感・ハイライトを描く。影は線の下、ハイライトは上へ | 基本色や本描きの変更を無断で代用する | **実際の描画**。影不要のフラット画なら理由付きレビューのみ可能 |
| **⑥ 修正・確認（`refine`）** | 既存の可視レイヤーを描き直す・消す。必要なら修正レイヤーを重ねる | 古いActionを消して履歴を改竄する、工程を巻き戻す | 修正した場合はその操作を保存。**修正不要なら理由付きレビュー**で完了 |
| **⑦ 完成（`finish`）** | 画像と全行動履歴を確定・出力 | 新規の描画・道具変更、別工程への逆戻り | ⑥の完了後にControllerが一度だけ確定 |

**注意：** 「工程に一筆ある」と「その絵が上手い」は別問題。上記はまず**正しい制作経路を守れるかという機械的合格条件**。構図や画質の良し悪しは学習時のEvaluatorで別に測る。むやみに無意味な一筆を足しただけで高報酬を与えてはいけない。

## 3. レイヤーは色が線を隠さない順番にする

実行中に工程4の色を後から描いても、工程3の本描きを覆わないように、**「作る時系列」と「画像の上下」は分ける**。

最終の重ね順（**下 → 上**。先ほどの番号は工程順で、ここは画面への重ね順）：

```text
透明の修正レイヤー  correction   ← 最前面
ハイライト           highlight
本描き               final_drawing
影・質感             shade
基本色               base_color
------------------ 非表示にする補助レイヤー
下書き               sketch
ラフ                 rough
------------------
白い背景             canvas
```

`rough`は③本描きへの入場時に、`sketch`は④基本色への入場時にControllerが**非表示**にする。レイヤーを削除しない。過去の制作状態は履歴から再生できる。

- **`rough`、`sketch`、`final_drawing`** は別の描画レイヤーを持つ。
- ④基本色は`base_color`という役割で`final_drawing`の**下**に追加する。描いた順に単純な最上層追加をすると、本描きの線が色に隠れるため**不合格**。
- ⑤陰影の`shade`は本描きの下、`highlight`は本描きの上へ配置してよい。
- ⑥修正では既存の可視レイヤーに書くか、最上層の`correction`へ描く。**下書き・ラフを再表示して混ぜることは原則禁止**。
- 役割ごとの表示順は[工程のJSON正本](drawing_stage_workflow_v2.json)の`layer_z_order_bottom_to_top`。同役割の複数レイヤーは作成順。Rendererはこの順序で合成する。レイヤーのIDと役割を同一視しない。
- 実装時はv2専用の`create_layer(role)`と`set_layer_visibility`（Controller専用）を定義する。旧v1の「新規レイヤーは常に最上層」を**黙って書き換えない**。

## 4. 操作の許可はレイヤーで厳格に決める

AIが予測する操作と、固定工程Controllerが実行する操作を分ける。

| 行動 | 誰が発行するか | 条件 |
| --- | --- | --- |
| `create_layer(role)` | AI | 今の工程の`layer_roles`内に限って追加できる |
| `select_layer(layer_id)` | AI | 今の工程で書込可能な役割のレイヤーだけ選べる |
| `select_color` | AI | 0〜255の固定256色のみ。ブラシとは独立 |
| `select_brush`／`set_brush_params` | AI | 12プリセットと固定のサイズ・不透明度段階のみ |
| `stroke_v2`／`erase_v2` | AI | **現在選択中の書込可能なレイヤー**にのみ実行。描画・消しゴムmodeが一致すること |
| `advance_stage` | AIが提案→Controllerが受理/拒否 | **次の工程にだけ**進む。移行先IDはAIに選ばせない |
| `enter_stage`／`set_layer_visibility` | Controllerのみ | 工程ごとのレイヤー準備・補助レイヤーの非表示を記録 |
| `finish` | Controllerのみ | ⑥の受理後に**一回**確定。以降のActionは拒否 |
| `skip_stage`／`set_phase` | **v2では誰も不可** | 旧`set_phase`はv1再生のためだけに残す |

同じレイヤーを別工程で勝手に上書きしない（例：下書きの工程中に本描きを直接進めない）。**例外は⑥修正**：既に存在する可視の`base_color/shade/final_drawing/highlight`と`correction`を編集できる。以前の工程へ戻ったことにはならない。

`advance_stage`は**移行先を含まない**。Payloadは通常`{}`。何も描かずレビューして次へ進める場合だけ`{"review_reason":"..."}`を付ける。適法かはControllerが判定し、拒否時はActionを適用せず理由をログに残す。

**エラーにすべき例**：後戻り、工程飛ばし、`skip_stage`、書込不可レイヤーへの筆跡、終了後の筆跡、必要な一筆がない移行、根拠のないレビューだけの移行、制限到達で勝手に`finish`する行為。

## 5. 「スキップなし」と「描く必要がない」は両立させる

全7工程は必ず**入場・確認・完了**を記録する。画像の内容に合わせて「この工程では描く必要がない」と判断した場合だけ、Controllerに**レビュー理由付きで移行提案**を出せる。

| 工程 | 描かず進める条件 | 明示する理由コード |
| --- | --- | --- |
| ④基本色 | 明示的に**モノクロ線画のみ**の作品 | `monochrome_line_art_only` |
| ⑤陰影・仕上げ | 影・立体感を要求しない**フラットな画風** | `flat_style_no_shading` |
| ⑥修正・確認 | 現在の作品に修正点がないと判断 | `no_correction_needed` |

①ラフ、②下書き、③本描きでは**レビューのみは禁止**。実際の描画が必須。④⑤⑥はすべて工程へ入場してから、実描画またはレビューのいずれかで完了。**`skip_stage`は存在せず、後工程へ飛ぶこともない**。

レビュー理由は**その文字列を発行しただけで合格**ではない。Controllerはpromptや評価器の結果、工程内の状態をチェックし、理由が成立しなければ拒否する。画像の見た目が良いからといって③の本描きを飛ばせない。

⑥修正で**わざと傷や汚れを作ってから直させるのは禁止**。修正不要ならレビューでよい。無意味な修正Actionを推奨しない。

## 6. 工程移行・失敗・再生のルール

1. 初期`stage_id=rough`。必ず白紙から。工程入場時はControllerが必要なレイヤーを用意する（記録される`actor=system`）。追加レイヤーをAIが作ることも可能。
2. AIは現在のstage、prompt、**自分で更新したcanvas・layers・history**だけを見てActionを決める。学習用の元画像／特徴を渡さない。
3. `advance_stage`提案は「工程に入ってからの有効なストローク数」「受理できるレイヤー」「有効な画素変化」「レビュー理由」「Action budget」を検査する。
4. 必須ストロークは**その工程の許可レイヤーに実際の画素差分を残すAction**を数える。色を選ぶだけや、描いて同じ画素のままのストロークは数えない。①〜③では退出時にもその工程のレイヤーに非透明な描画が残っていることを要求する。
5. 次工程へ進むときだけ`enter_stage`と非表示操作を記録。過去のActionやlayerを削除せず、どの時点でも同じ状態をReplayできる。
6. 移行拒否／不正Actionは結果と理由を**Trialログに保存**し、適用済みのAction列の`seq`を消費しない。
7. 予算切れ・異常終了時は`DrawingDraft`＋失敗理由として保存し、**完成品扱いしない**。⑥を正しく完了した場合にのみControllerが`finish`を確定。
8. 旧`drawing-episode/v1`は`set_phase`自由・最上位追加・整数`hard_round_v1`のままでGoldenを維持。**上記はv2だけ**の契約。

## 7. 各工程で何を学ぶか：見本画像だけを評価する

学習画像から`rough`の正解ラフや`sketch`の正解下書きを**復元・捏造しない**。AIは自分の工程内の筆跡を試し、**Evaluatorのみ**が学習用画像と現キャンバスを比較して報酬を出す。

| 工程 | 主な学習・報酬の目安（正解の中間画像は不要） |
| --- | --- |
| ラフ | 全体の位置、大まかな形、構図、占有領域 |
| 下書き | 比率・輪郭・構造の整合 |
| 本描き | 主要な形や線・面が安定していること |
| 基本色 | 主要な色・広い面の配置 |
| 陰影・仕上げ | 光、陰影、質感、ハイライトの改善 |
| 修正・確認 | 変更前より完成品質が改善、または修正しない方がよいことの判断 |
| 完成 | 未見画像・未見promptへの忠実度、画質、行動効率 |

工程ごとの報酬は**最終画像から計算する代理評価**であり、絵師が実際に行った行動の教師ラベルではない。レイヤー・道具・軌跡はAIが試して選ぶ。ステージを固定することで探索空間が減っても、**これだけで学習が収束する保証はない**。無意味な筆跡と形式的な工程進行を高評価にしない。

## 8. 受け入れ試験

**機械可読な正本**：[drawing_stage_workflow_v2.json](drawing_stage_workflow_v2.json)。工程移行の原子性・書込権限・選択状態・失敗時の扱いは[StageControllerの詳細な実装契約](stage_controller_contract_v2.md)に、画像からの段階別採点は[工程別Rewardの仕様](stage_reward_v2.md)に分離して記載する。以下を自動テストへ落とす。

1. `rough → sketch → final_drawing → base_color → shading → refine → finish`以外を拒否。**全工程を通り、skipなし**。
2. rough/sketch/final_drawingでそれぞれ専用roleのレイヤーに有効な筆跡が残る。レイヤー作成や工程変更だけでは合格しない。
3. 他工程・非表示・背景レイヤーへの書込を拒否。修正時のみ既存の可視役割へ書き込める。
4. 作成順ではなく最終z順で合成し、④の基本色が③本描きの線を隠さない。③への入場でrough、④への入場でsketchを非表示にする。
5. モノクロ・フラット・修正不要のときも、④⑤⑥の工程は入場・レビュー理由・退出が履歴に残る。`skip_stage`を受理しない。
6. 不正な移行・予算切れ・途中終了を完成扱いしない。 `finish`はControllerが一度だけ発行。
7. Replayから全中間レイヤー状態と最終RGBAが完全一致。学習用の元画像はPolicyの観測に入らない。
8. 画像だけで学習し、工程内で実際のActionを試し、報酬からPolicyパラメータが更新される。固定スクリプトではない。

現時点で検証できるのは**JSON契約の静的整合と旧v1 Golden**。**v2 Controller・Action validator・Renderer・Stage評価器・本当の学習**は未実装。テスト/ビルド成功をこれらの完成と誤認しない。
