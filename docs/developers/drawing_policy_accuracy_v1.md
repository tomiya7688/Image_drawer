> **対象読者:** DrawingPolicy・学習器・Evaluator・実験評価担当
> **目的:** **画像だけを教材に、AIが描いて試して上達する**学習方法を定義する。人間の実演データは必要としない。
> **状態:** 新しい主要学習仕様の設計案。学習器、最適化、画像品質の実測値はまだ存在しない。

# DrawingPolicy：実際に描いて上達する学習と評価

## 0. まず、学習の目的

正解として渡せるのは**完成画像だけ**。タグと文章は自動抽出器が生成する。人間が何色を選んだか、どこへ線を引いたか、どんな筆圧だったかは分からないし、**学習に必要ない**。

DrawingPolicyは**文章と白紙**から自分でラフ・下書き・本描き・着色・仕上げを行い、描いた結果を元画像と比較した報酬によって、次回のAction選択を改善する。

- **固定されるのは工程の順序**：[固定制作工程](fixed_drawing_workflow_v2.md)の `rough → sketch → final_drawing → base_color → shading → refine → finish`。
- **学習するのはその中身**：色、ブラシ、レイヤー、サイズ、透明度、筆圧、座標、消去、進行時期。
- **教師ありで人間の次Actionを当てる課題ではない**。従来のhuman Behavior Cloningとheld-out作者テストは本製品の必須条件から外す。
- **学習時に元画像を見てよいのはEvaluatorだけ**。推論時は元画像自体が存在しない。

最初から人間と同等の品質が出る保証はなく、画像だけで試行錯誤する学習は高コストである。実験で改善できた範囲を報告する。

## 1. 何をPolicyに渡すか

```text
DrawingPolicy(
    prompt,
    own_canvas_and_layers,
    tool_state,
    current_stage,
    own_action_history,
    remaining_budget,
    seed
) -> next_action
```

**禁止**：target_image、target_image_embedding、教師Action、未来の自分のAction、targetとの距離/差分画像、学習用RewardをPolicyの**観測入力**に含めること。

- **学習中も**Policyへ入るのは文章と自分で描いた途中状態だけ。Evaluatorが目標画像を見てRewardを計算し、Trainerがそれを使ってパラメータを更新するのは許可。
- 教師画像に由来する**固定の中間下書き・ラフ画像**をPolicyへ渡さない。正解画像から「人間が描いたであろう筆跡」を逆算しない。
- 各Stageの現在位置、残予算、直近の描画状態はPolicyの正当な入力。自分が出したActionとその画素のReplayは完全に記録する。
- 履歴が長い場合の要約／局所高解像度cropは自分のstateとhistoryのみから計算し、学習時・推論時で同じ規則を使用する。

## 2. どのActionを学習するか

| 出力 | 学習対象 |
| --- | --- |
| 次のAction種別 | レイヤーの作成・選択、色・ブラシ選択、調整、描画、消去、工程を進める、完成 |
| 色 | **固定256色**の`color_id`を分類 |
| ブラシ | **独自12プリセット**を分類。色とは独立 |
| サイズ | [19段階](brush_control_levels_v2.md)のlevel ID |
| 不透明度 | [11段階](brush_control_levels_v2.md)のlevel ID |
| 筆圧 | 各点の11段階と、一筆全体の5パターン（補助head） |
| ストローク | サブピクセルの可変長座標列、傾き、終了判断 |
| 工程移行 | 現在の工程を**終えてもよいか**だけを予測。飛び先は固定Controllerが決める |

ストローク座標を一つの巨大分類にせず、点を1つずつ予測して最後に`POINT_END`を出す。幅、色、ブラシと座標の直積分類は禁止。工程外Action、ブラシ不一致、予算超過はEngine/Controllerが拒否する。

最初のAction decoderの実装候補は、現在画像の視覚encoder＋文章encoder＋自己履歴要約＋条件付き分類headで構成する。各headを事前に用意しても、その数だけ学習できたと主張しない。

## 3. 工程は固定するが、正解の筆跡は与えない

[工程JSON](drawing_stage_workflow_v2.json)によって、最初は`rough`。必須のラフ・下書き・本描き・仕上げにはそれぞれ実際の描画Actionが必要。

- ラフでは構図・大まかな形、下書きで形状構造、本描きで主要な形・面、着色で基本色、陰影で明暗、仕上げで細部や修正を**試行して学ぶ**。
- ただし「こういうラフ線を引け」という人間の正解Actionは無い。**画像比較から各工程の状態を評価する**だけ。
- 基本色・陰影は明示的なモノクロ・フラット作品でのみskip候補。必須工程はskip不可。Stage後戻りも不可。
- 規則が自動で作るのは工程の許容順序。**どこを描くかは決して固定スクリプトにしない**。

## 4. 基本の学習ループ

```text
学習画像だけ登録
    ↓
選択したTagExtractor/CaptionExtractorで文章生成（結果を凍結・キャッシュ）
    ↓
Policyは文章＋白紙でラフを描く
    ↓
下書き→本描き→基本色→陰影→仕上げを順に描く
    ↓
Evaluatorが各段階・最終画像と元の画像を比較
    ↓
Trainerが報酬を用いてPolicyのパラメータを更新
    ↓
学習前後を同条件で比較・新しい試行
```

**v0の学習Baselineは**、少数の合法Action候補をPolicyからサンプリングし、Rewardで相対的に良かったActionの確率を上げる方法（REINFORCE＋状態価値Baseline等のpolicy-gradient、または同等の検証可能な手法）。採択/棄却、学習前checkpoint、更新後checkpoint、ログ確率と報酬を保存する。

「報酬を計算した」だけでは未学習。**本当に更新可能パラメータが更新され、同条件で改善すること**をテストする。差分描画器を将来追加して直接画像損失を伝播してもよいが、人間の筆跡を偽装しない。

### なぜ単純な最終画素一致だけで学ばせないか

長いAction列では、最後に減点されても**どの筆跡が悪いか分かりづらい**。不透明度・レイヤー・位置・描く順番の選択肢も多い。

対策として、低解像度の形、輪郭、色、知覚的特徴、文章適合、無効Action、Action数、途中の画像距離改善を**別成分のReward**として計算する。具体的重みはexperiment configで凍結・記録。目標画像から工程別の代理特徴を計算してもよいが、Policyにそれを観測させない。

## 5. 何を精度と呼ぶか

| 検証段階 | 必須指標 |
| --- | --- |
| レンダラ再生 | 保存EpisodeをReplayした各レイヤーRGBA完全一致 |
| 画像登録と抽出 | 成功率、タグ/文章の品質、抽出器のバージョン差分 |
| Action合法性 | 不正Action率、最大予算超過、Stageスキップ違反 |
| 試行学習 | 同じ画像・同じseed・同じ計算量でのReward向上、未学習Baseline比較 |
| 画像品質 | 未見作品の構図・形状・色・知覚距離・プロンプト一致 |
| 固定制作工程 | ラフ→下書き→本描き→…→仕上げの履歴・レイヤー・各工程の描画有無 |
| 一般化 | 未見画像/未見prompt、複数画風への改善、失敗例の開示 |
| 予算 | 一作品のAction数・生成/学習時間・計算資源 |

**工程の順番を守ることは画像品質の向上と別の問題**。順番だけ守る固定動作では合格しない。比較に使う評価画像はPolicyの学習やReward重みの調整に使用しない。

## 6. 最初の実装で確認すること

1. **画像だけ**で登録でき、TagExtractor/CaptionExtractorを利用者が独立に変更できる。
2. Policyが目標画像を見ず、同一prompt/seed/checkpointなら**目標画像だけ変えても最初のActionが変わらない**。
3. ラフ→下書き→本描きの順を必須とし、Stageのスキップや後戻りはEngineが拒否する。
4. 学習画像の目標を使うEvaluatorからRewardを取得し、**Policyの実際の選択分布/重みが変わる**。
5. 単純な図形の画像数件だけから、自分で描いたものを比較して、学習前よりRewardと画質が改善する。
6. 未見画像・未見promptで再評価する。訓練画像のまるごと暗記だけでは成功と呼ばない。
7. 学習後は**文章だけ**で画像を生成し、全Action履歴から画像が再生できる。

## 7. Version、データと学習ログ

画像datasetのhash・権利・train/val/test group、Tag/Caption抽出器ID/hash、PromptBuilder、palette、brush set、control levels、Renderer、Stage workflow、Rewardのversion、Policy checkpoint、seedを一緒に記録。

それぞれの試行に`target_image_id`（**Policyの観測ではなくEvaluatorの参照**）、自動抽出したprompt、各Action、各Reward、最終画像、Policy更新前後を保存する。失敗trialやbudget超過を隠さない。

## 8. 精度に関する公開ゲート（画像データ評価後）

- 同条件の未学習Policy／単純な規則モデルよりも、**学習後Policyが未見画像で改善する**。
- レンダラ/Action/Stageの正確性は100%の再生試験で保証し、作品の見た目は画像距離と**独立した人間評価**で検証する。
- 実験回数、seed数、平均/分布/95%信頼区間、学習前後の結果と失敗例を残す。**高い画質や必ず収束することは保証しない**。
- 「元画像から描画行動を推定した」「人間の絵師の操作を完全に学習した」とは呼ばない。**自分で描き、比較して改善するモデル**と正確に説明する。

## 9. 互換性と未実装

`drawing-episode/v1`の古い整数座標・hard_round・`set_phase`は**旧再生試験専用**に維持する。高精度の新しい12ブラシと[段階制御表](brush_control_levels_v2.md)、[固定工程](fixed_drawing_workflow_v2.md)はEpisode v2の設計として実装前にスキーマと画素goldenを別途完成させる。v2の描画/学習実装はまだ完成していない。
